# 2.3 · 头像、到访徽章与私人美食日记界面

## 使用

- 点击首页自己的头像，或“我们 → 头像与昵称”，选择相册照片。支持预览、放大、左右/上下调整、保存、替换和恢复默认。
- 云端头像在同一空间的首页、个人档案、成员列表和双方评价中显示。本机头像独立保存，不自动上传。
- 记录默认仍按用餐时间排序，首页最近吃过仍按上传时间；同店多次打卡、独立双人评价和单店一个榜单席位不变。
- 到访纪念徽章：1 次初见（绿）、2–3 次回头客（蓝）、4–7 次熟客（紫）、8–14 次常客（金）、15 次起私藏宝店（玫瑰）。仅计同一店铺的未删除吃过记录，想吃和双方分别评价不增加次数。详情可查看下一等级和规则；不是商家付费会员。

## 视觉参考与取舍

浏览了以下官方产品介绍，以功能层次与私人记录体验为参考，不复制品牌素材或原样照搬界面：

- [Beli](https://beliapp.com/beli-home)：餐厅收藏与个人餐厅档案。
- [Day One Shared Journals](https://dayoneapp.com/shared-journals/)：邀请亲密的人共同留下照片与日记。
- [Apple 手记](https://www.apple.com.cn/newsroom/2023/12/apple-launches-journal-app-a-new-app-for-reflecting-on-everyday-moments/)：照片、日常回忆与个人记录。
- [Swarm](https://apps.apple.com/us/app/swarm-check-in-explore-map/id870161082)：地点到访历史与回看。
- [Polarsteps](https://www.polarsteps.com/)：照片故事、足迹统计和隐私控制。

本版设计采用奶油白、深绿和暖橙点缀。强化食物照片、四项评分/人均、双方身份；补充首页快捷统计、统一线条图标、矩形照片胶卷、打卡时间线和个人档案封头。不新增广告、公共社交或额外定位权限；无远程字体与装饰图片依赖。

## 搜索缩放与照片闪动

- 搜索输入原为 13px，现与其他可编辑输入统一至少 16px，降低手机浏览器聚焦自动放大的触发风险。保留设备宽度 viewport 与用户双指缩放，不禁用无障碍缩放。Enter 收起搜索键盘。
- 原来定时云同步每次都会重建内容，包括图片节点。现比较快照，无数据变化不重绘；有评分等文本变化时进行节点级更新，不移除已加载图片。
- 签名链接在有效期内复用；缺失文件或签名服务失败保留 5 分钟负缓存，避免每 20 秒反复请求同一缺失文件。手动刷新可立即重试；到期仍正常更新签名，不永久公开图片。
- 详情展开状态、搜索框焦点、当前筛选和滚动位置不因普通后台同步而重置。

## 隐私与失败处理

- 新增 `food-avatars` 私有桶，只接收 JPEG、最大 1 MiB。原图先在设备端按方向解码、裁剪为 512×512 JPEG，不上传原始文件或原图 EXIF。
- 路径为 `space/user/uuid.jpg`，成员可读同空间头像；只能上传自己目录。无公开读取、无覆盖写权限，仍被档案引用的头像不能删除。
- `save_member_profile` 检查登录、成员身份、昵称、旧版本、文件路径归属及存在性；原子保存昵称和头像。客户端不能绕过 RPC 直接改头像字段。
- 每次替换使用新路径；上传失败保留原头像与草稿，丢失保存响应可幂等重试，旧文件按引用检查后清理。退出登录清除云端头像显示与草稿。
- 本机保存使用 IndexedDB 事务和冲突检查；导出嵌入头像图像，导入只接受限长的栅格 data URL，不保留签名链接，也不覆盖已有本机头像。
- 已有缺失原文件的历史照片仍显示占位；不会虚构图片或自动删除用户记录。

## 回归验证

- 模型测试：徽章每个阈值、重复/已删/想吃/同名分店隔离、图片链接正负缓存、头像备份安全、既有评分排序逻辑。
- 浏览器测试：头像裁剪实际像素、处理中禁止保存、文件解码失败、存储失败重试、持久化、取消、恢复默认、320/393/560px 编辑布局。
- 搜索验证字号与 viewport scale；验证后台刷新及文本修改不替换已加载图片、不产生额外 load 事件；保留离线/备份/多标签/回收站/复访/榜单回归。
- 使用隔离临时账号和空间测试真实 Supabase 头像权限、大小限制、私有读取、失败重试、提交后响应丢失、另一半同步、过期编辑保护与旧文件清理；结束后核对旧数据行数未变并清理测试资源。
- 手机界面使用浏览器触屏模拟验证，不替代具体 Android 或 iOS 真机测试。
