# 美食地图 2.0 更新与检查记录

更新日期：2026-09-16。沿用原网站、账号、情侣空间及数据库；历史记录不重写。

## 已修复与完善

- 照片：增加图片解码兼容方案、压缩失败提示和处理进度；处理未完成时不能提前保存。已有照片可在编辑页查看，自己的照片可移除或替换，另一半的照片保留。支持点击看完整大图。
- 保存：本机照片与记录一起写入 IndexedDB，写入成功后才提示保存完成。云端照片先上传，再用数据库事务一起保存餐厅、自己的评价与照片关联。失败保留表单，重试沿用同一编号，避免重复记录。移除照片后会清理对应存储文件。
- 数据隔离：退出账号后切换到本机档案，不继续展示前一账号的云端数据。登录后尚未加入空间时，提示先加入空间。同步失败不会偷偷改成本机保存。
- 双人逻辑：每个人只编辑自己的评价；同时修改餐厅信息时检测过期版本，避免覆盖另一半的新修改。新增明确的两位成员列表、等待加入状态，刷新与实时同步均包含成员和昵称。
- 评分：默认未评，保留历史原始分数。主评分为味道、性价比、环境，均按 10 分制展示；人均独立显示，0 元与未填区分。服务、颜值作为可选补充。综合分仅使用三项齐全的评价，权重为味道 50%、性价比 30%、环境 20%。
- 展示：餐厅卡片、详情和榜单均展示三个主评分与人均；新增按性价比、味道、环境、人均及综合排序。想吃记录的人均显示为预算，不进入实付统计。
- 筛选：共同最爱要求两人都收藏；待我评分与待另一半评分分开；推荐菜可搜索。口味接近度根据两人的味道分差计算，避免不同维度相互抵消。
- 兼容：旧本机记录与照片迁移到 IndexedDB，原 localStorage 数据保留；备份导入只在本机模式执行，合并而非覆盖原记录。导出包含可读取的图片内容，不只保存会过期的网址。
- 手机与缓存：SDK 随网站部署，不再依赖第三方 CDN；更新离线缓存，避免误删同一域名下其他应用的缓存。登录界面只展示普通用户需要的邮箱操作。

## 验证结果

- 8 项数据模型测试通过：缺失评分、加权计算、共同收藏、想吃隔离、待评与菜品搜索、0 元人均、口味差异、旧备份与本地日期。
- 10 项浏览器流程测试通过：照片新增、查看、编辑、移除与刷新后保留；格式不支持的提示；旧数据迁移；320/393 像素手机与桌面布局；写入失败后重试；照片处理中禁止提前保存；离线重新打开与缓存隔离；验证码过期与重发倒计时；备份合并与内容转义。
- 真实 Supabase 集成测试通过：在独立测试空间中创建三个临时账号，验证两人加入、第三人拒绝、跨空间不可读、私人照片共享、独立评分、重复请求幂等、事务失败回滚、同时编辑冲突，以及两个独立浏览器中的实时同步。
- 云端照片替换测试通过：自己的照片被替换，另一半的照片保留；旧文件关联与存储文件均被清理。
- 所有临时账号、测试空间及测试图片已清理；测试前后原有数据表行数一致。
- 生产依赖安全审计未发现已知漏洞。测试使用桌面 Chromium 的移动尺寸模拟，并非在用户的实体安卓手机上运行。

## 已知边界

检查时发现 3 条现有照片记录没有对应的存储文件。更新保留这些记录并显示明确的不可用提示；文件内容无法仅凭数据库记录还原，需要原图重新上传。打不开但仍存在的图片可先点刷新或大图中的“重新加载”。

本机档案支持离线记录，云端保存需要网络。HEIC 等格式取决于浏览器原生解码能力；不支持时会提示转换为 JPG、PNG 或 WebP。历史自动填入的 8 分无法与用户主动打的 8 分可靠区分，因此不自动改动。

## 维护

运行 `npm ci` 安装固定依赖；`npm test` 检查数据逻辑；`npm run test:ui` 执行浏览器流程；`npm run serve` 打开本地预览。SDK 更新后运行 `npm run vendor` 重新生成浏览器包与许可证说明。

`npm run test:cloud` 需要当前设备已登录该项目的 Supabase CLI。它会在真实项目创建临时测试账号、空间和图片，使用完毕后清理，不发送测试邮件；项目密钥仅保留在进程内存。需要可用的本机代理与 Chromium，脚本中的默认路径对应本次开发环境。

发布前执行 `supabase db push --linked --dry-run` 核对迁移，再应用必要迁移。网页部署使用现有 GitHub Pages；更新应用资源时同步增加 HTML、模块引用与 Service Worker 的版本号。
