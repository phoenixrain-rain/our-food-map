# 2.8 · 选店对比

整理日期：2026-09-23。围绕“今晚到底去哪家”，补充私人档案内的选店工具，不新增公共评论或商家数据服务。

## 怎么用

1. 从“记录 → 选店对比”或“今晚吃啥 → 已经有几家备选？”进入，也可从某次打卡详情点“加入选店对比”。
2. 搜索店名、城市、分类、地址或标签；可只看有吃过记录 / 有想吃计划的店。暂选 2–3 家，再点“开始对比”。
3. 一起看味道、性价比、环境、实付人均、想吃预算、实际到访次数和地址。手机上可左右滑动，指标列和店名表头固定；点击来源日期可核对原始那一顿。
4. 相同分数不强行选赢家，只有至少两个已知且不同的数值才提示本组较高/较低；0 元是有效实付。预算不参与实付人均的高低提示。

暂选只存在当前页面会话，关闭面板可保留；刷新或重新打开页面后需要重选。它不是云端共同投票，不会给另一半发通知，也不会修改、合并或新建打卡。页面已缓存时可离线使用本机档案；云端的既有离线限制不变。

## 数据口径

- 按空间和稳定店铺 ID 去重，同名分店不自动合并。某店多次复访只占一个对比位置。
- 三项评分仅来自用餐日期最近、双方均评完三项主评分的那次打卡，逐项取双方平均。用餐日期缺失排后，同日按上传时间；与榜单一致，不跨打卡拼接两人评价，不使用历史最高成绩。
- 没有完整共同评分时显示“待双方评完”，不展示单方均分冒充双方评分。新一次未评完时保留之前最近一次共同成绩，并明确提示。
- 实付人均取最近一次吃过的记录；这次未填就显示未填，不悄悄借用旧价格。想吃预算取最近上传的想吃计划，独立显示和追溯，不冒充实付。
- 评分与人均可能来自不同打卡，所以分别提供来源日期和跳转，不能误读成同一顿的组合成绩。
- 删掉某顿、移动店铺归属、另一半补评或本机刷新时重新计算；如果所选店已经没有有效记录，自动从暂选移除。普通搜索和来源筛选不清空暂选。
- 候选较多时先显示前 30 家并明确提示，可搜索找到后面的店；没有截断正式档案。最多同时暂选 3 家。

## 设计依据与边界

参考 [NN/g：Mobile Tables](https://www.nngroup.com/articles/mobile-tables/) 关于移动端限制对比对象数量、固定行列标题和提示横向滚动的研究。这里只借鉴信息组织，不复制素材；本项目的评分和人均来源规则由自身产品定义。

本组高低提示仅是已填私人记录的相对差别，不判断实时营业、当前菜单价格、其他顾客评价或哪家“客观最好”。浏览器验证采用触屏尺寸模拟，不是实体安卓/iOS 真机认证。
