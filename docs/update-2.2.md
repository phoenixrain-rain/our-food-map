# 美食地图 2.2：一家店，多次打卡

## 产品研究与取舍

- [Swarm 的官方产品介绍](https://apps.apple.com/us/app/swarm-check-in-explore-map/id870161082)把每次到访加入时间线，并允许保存笔记和照片。这里借鉴“地点”和“到访事件”分开保存，而不是反复覆盖上一条。
- [Letterboxd 官方 FAQ](https://letterboxd.com/about/faq/)明确区分独立作品数和观看日记次数；同一作品可以有不同日期的记录与不同评分。这里借鉴“店铺数”和“打卡次数”分开统计。
- [Beli 官方介绍](https://beliapp.com/beli-home)以餐厅清单和分享为核心；其公开页面没有给出足够明确的复访评分计算规则，因此本项目不声称照搬其算法。

本项目采用自己的明确规则：一家店在榜单只有一个位置，选择用餐日期最近、双方三个主评分完整的一次打卡。这样不会因为某家常去的店记录多而占满榜单，也不会取历史最高分掩盖最近的体验。新一次尚未评完时，沿用上一次双方完成的成绩。两个人必须评价同一顿，不跨不同次打卡拼接分数。

## 使用方式

1. 记录页默认“按店铺收纳”，每店一张卡，显示去过几次；展开可以逐次查看日期、人均、评分和照片，点某一次可补评价或编辑。
2. 记录页默认按用餐日期倒序。同日按上传时间倒序，未填日期排最后；可切回“最新上传”。首页“最近吃过”继续沿用此前指定的上传顺序。
3. “逐次打卡”视图展示每一顿，并标注首次/第几次打卡。同一天可以记录多顿，系统只提醒已有打卡，不禁止再次记录。
4. 详情或店铺卡中的“再来一次”会沿用店名、城市、分店和分类，但人均、评分、照片、菜品和评语均不复制。用餐日期默认为设备当天，可补录过去的日期。
5. 如果当天已经有打卡，会给出“打开当天已有打卡”入口。另一半是为同一顿写评价时，应该打开原记录，不需要新建一次。
6. 旧记录可以在“编辑这次打卡 → 这次去哪家店？”选择已有店铺，确认后只调整本次归属。选择“新店 / 作为独立店铺”可拆开；不合并或覆盖任何评价和照片。
7. 历史同名店不自动归并，防止不同分店被混在一起。遇到同名新建会提示选择已有店铺。
8. 删除只影响单次打卡，回收站恢复后仍归原店铺；其他打卡不受影响。计数只包含未删除的打卡。

## 数据与统计规则

- 新增私有的 `food_places` 身份表，`restaurants` 仍保存每次打卡快照，通过 `place_id` 关联店铺。保留旧打卡编号、上传时间、双方评价和照片路径；不会重写旧分数或把历史记录擅自拼接。
- `(place_id, space_id)` 外键与行级权限禁止把打卡挂到其他空间的店铺。旧页面不传店铺编号时仍可创建新记录；修改旧记录不会丢失已经设置的店铺归属。
- 榜单的味道、性价比、环境、综合和人均都来自同一次入选打卡。该次人均未填时不入人均榜，不偷用其他次的旧价格。
- 店铺卡默认展示用餐日期最近的一次符合筛选的已吃记录；未来想吃计划不顶替已吃记录。按“最新上传”时展示最近上传的匹配记录。展开历史始终可以回看全部。
- “吃过的店铺”按店铺去重，同时展示打卡次数；人均按各次已填金额的打卡计算。口味接近度和分类频率也以打卡为单位。随机选店按店铺去重。
- 每人每次打卡最多 8 张照片；复访不占用上次的额度。备份保留活跃记录和回收站的店铺关联。
- 自动同步后保留正在展开的历史，避免阅读到一半被折叠。实时监听就绪和重连时重新读取，并在页面可见且联网时每 20 秒兜底检查一次；后台与离线时不轮询。

## 验证

- 16 项模型测试、17 项浏览器流程测试通过，覆盖日期排序与缺失日期、复访的空白评分、每店单一榜单位、归并/拆分、删除恢复、备份、多标签页、600 条记录与离线使用。
- 独立临时空间内的真实双账号集成测试通过：第二人补评后更新排名，旧图片与评价不被覆盖，归并/拆分过期版本被拒绝，跨空间绑定被拒绝，删除和恢复只影响一顿。
- 额外阻断测试浏览器的所有 Realtime WebSocket 消息，确认前台自动检查仍能补上另一人的修改。一次测试捕获到未及时同步，改进后多轮复测通过；不是只延长测试等待时间。
- 临时测试账号、空间与图片均清理，测试前后原有表行数一致。没有把正式历史同名记录擅自合并或删除。

同步处理参考 [Supabase 官方排障说明](https://supabase.com/docs/guides/troubleshooting/realtime-postgres-changes-troubleshooting)：连接就绪不等于数据库监听立即就绪，断线也可能漏掉通知；通知用于触发重新读取，并辅以前台定时核对。

测试命令与环境说明沿用 [2.1 更新记录](update-2.1.md)。移动端检查使用 Chromium 手机尺寸模拟，不等同于全部实体安卓手机兼容性验证。
