# 2.6 · 看得见的版本与安全更新

整理日期：2026-09-18。2.5.2 上线复核后，针对旧页面/PWA 长时间打开、不易知道是否升级的问题继续完善。无数据库迁移，没有清理用户站点数据或改写正式记录。

## 使用方式

- “我们 → 版本与更新”显示当前页面版本、已确认的离线版本、近期改动和“检查更新”。不再依赖一个不会随页面更新的旧网址参数来判断版本。
- 从 2.6 开始，已安装的新离线版本会显示顶部提示。点击“更新并重新打开”才切换页面，并把网址的版本参数更新；不会自动刷新正在编辑的内容。
- 正在上传/保存、编辑食记、处理头像或暂存草稿时阻止重新打开，提示先保存或暂存。已存的本机档案和草稿不删除，也不注销云端登录。
- 离线时不发起版本检查；如果新版已经下载完整，仍可主动切换到已缓存的新版本。
- 下载失败、尚未启用离线缓存、旧 Service Worker 无法回答版本时给出准确说明，不声称“已经最新”或让用户清空站点数据。
- 本轮之前已经打开的 2.5.x/更早页面没有这个新入口，仍需先手动重开一次最新版。新增提示不能逆向添加到尚未刷新的旧 JavaScript 中。

## 实现与约束

- `lib/updates.js` 提供版本比较、MessageChannel 查询、安装状态观察、安全重新打开和 UI 状态。
- Service Worker 仅回应自己的版本号，不接收凭据，不传递记录、图片或账号数据。沿用原有应用外壳缓存/激活，不增加云端数据缓存或后台上传。
- 只接受有界的三段数字版本；没有把服务返回的 URL 当更新跳转地址。更新时只替换本站网址的 `v` 参数。
- 正式站点注册使用 `updateViaCache: none`；监听安装和控制器变化，明确区分当前页面、安装中、已经安装和检查失败。
- 资源 2.6.0，缓存 `our-food-map-shell-v11`；只读发布自检新增校验页面和 Worker 的版本常量。
