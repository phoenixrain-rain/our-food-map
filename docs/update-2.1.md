# 美食地图 2.1：删除、双人榜单与时间排序

更新日期：2026-09-17。继续使用原 GitHub Pages 网站与 Supabase 项目。

## 这次改动

- 记录详情底部新增“删除这条记录”。二次确认后移入回收站，从双方首页、记录列表、榜单、统计及随机推荐中移除。
- “我们 → 回收站”可以恢复。删除不物理清理餐厅、双方评价或照片文件，恢复保留首次上传时间；两位空间成员均可操作。
- 云端删除与保存使用相同的事务锁；过期删除请求会被拒绝，网络失败可重试。同一操作重复提交不会反复切换状态。
- 另一方删除时，已打开的详情会关闭，编辑中的草稿保留并提示不能保存。数据库同时拦截旧页面对已删除记录的编辑。
- 榜单以一条记录为单位，每条只排一次。双方均填完味道、性价比和环境才入榜；单人评价、未完成评价、想吃和回收站记录不入榜。不同日期的真实复访仍是独立记录，不按店名擅自合并。
- 性价比、味道和环境按双方平均分降序；综合仍为味道 50%、性价比 30%、环境 20%；人均榜按已填实付金额升序，0 元有效、未填不参与。分数相同时按上传时间降序，再按固定编号排序，避免位置抖动。
- “最近吃过”和记录默认排序按首次上传时间 `created_at` 从新到旧；补评分、编辑用餐日期、删除后恢复都不会把旧帖顶上来。详情同时展示用餐日期和上传时间。
- 分类改为可输入的推荐列表：提供火锅、川湘菜、面馆粉店、甜品烘焙等常用分类，也可填写最长 40 字的自定义名称。保存后会成为后续输入的建议，历史分类不重写。
- 本机修改改为 IndexedDB 事务内读取最新快照并更新，防止两个标签页分别保存时相互覆盖；旧标签页不能复活已经删除的帖子。
- 备份包含回收站。合并旧备份不会自动恢复已删除的同编号记录。
- 网页、模块和离线缓存统一升级至 2.1，保留照片处理、独立评分、验证码登录、备份等 2.0 功能。

## 检查结果

- 11 项数据模型测试通过，包括双方平均、单人不入榜、记录去重、上传时间排序、0 元和未填、回收站备份。
- 15 项浏览器流程测试通过，包括照片新增/编辑/删除/重试、旧数据迁移、删除确认/取消/写入失败/刷新/恢复、恢复后双方评价和照片保留、自定义分类、备份不复活已删除记录、多标签页并发、600 条记录、离线重开、验证码错误与倒计时、320/393 像素手机及桌面布局。
- 真实云端集成测试通过：三个独立临时账号、一个测试空间、两个浏览器会话；覆盖第三人权限拒绝、私有照片、双人实时同步、删除失败重试、对方正在编辑时删除、对方恢复、过期版本拒绝、重复请求幂等、恢复后照片可读取及榜单回归。
- 所有临时账号、测试空间和图片已清理；测试前后原有数据表行数一致。没有删除或合并正式历史记录。
- 生产依赖安全审计结果：0 项已知漏洞。

测试使用桌面 Chromium 的移动设备模拟，不能替代所有品牌实体安卓手机的兼容性验证，也不代表不存在任何未覆盖的问题。

## 历史数据说明

只读检查发现两组同店、同日期、保存时间相隔约两秒的历史重复记录，其中各有一条只有发帖人的评价。新版不再让单人评价副本入榜；可在详情中手动把不需要的副本移入回收站，不会自动处理正式记录。

先前发现的 3 条历史照片记录缺少对应的存储文件。它们保留不可用提示，但无法仅凭记录恢复原图，仍需要重新上传。其他照片上传、替换和双人可见性已验证。

## 复测与维护

运行 `npm test`、`npm run test:ui`。有此项目管理权限及本机代理时，可运行 `npm run test:cloud`；它会创建和清理独立测试数据，不发送邮件，密钥只在进程内存使用。

数据库迁移为 `supabase/migrations/20260917000000_record_trash.sql`，是增量迁移，不清空任何正式数据。网页发布后需刷新或关闭桌面应用再打开，使旧页面加载 2.1 资源。
