# 2.5.1 · 相册实时更新与迟到请求保护

整理日期：2026-09-18。完成 2.5 发布验证后，继续检查并修复照片大图的同步边界。没有数据库迁移，没有修改正式用户记录。

## 问题与改动

- 已用合成数据复现：相册停留在第 2 张时，刷新后的照片列表已删除它，但大图仍显示旧的 `2 / 3` 和旧照片。现在每次档案更新都按照片 ID 对齐，保留仍存在的当前照片；它被删除后显示临近的剩余照片。
- 当这一顿进入回收站或全部照片被移除时，关闭相册并清空图片地址、照片说明和内存引用。仅关闭遮罩不足以清理隐藏内容。
- 相册打开期间，新的有效图片地址和成员昵称也能更新；相同图片地址不重复设置 `src`，保持已解码照片稳定。失败状态保留到显式重试或地址实际变化，避免后台刷新反复触发加载。
- “重新加载”固定本次照片 ID、原路径、原地址、请求代次和登录代次。切换照片、关闭/重开相册、账号切换、照片被移除或已有更新地址时，迟到结果不再覆盖当前大图或档案。只有主动重试可以重新加载相同地址。
- 新增键盘左右方向键切图，首尾边界不越界；相册内 Tab/Shift+Tab 循环可用按钮，关闭后回到原入口（入口仍存在且可见时）。保留原有触屏上一张/下一张按钮和浏览器缩放，没有添加手势拦截。
- 将相册协调独立到 `lib/gallery.js`，便于用延迟签名请求做确定性测试，不需要使用真实账号制造竞态。
- 应用资源升为 2.5.1，离线缓存 `our-food-map-shell-v9`；新增模块进入离线清单。

- 新增 4 项浏览器测试：先确认旧版失败，再验证删除/刷新、地址更新、图片节点与零额外 load、键盘/焦点、网络失败重试，以及切图/关闭/退出/移除/更新后的迟到响应。
- Node 30 项、完整浏览器 40 项通过，共 70 项；发布自检覆盖 13 个前端模块、21 项离线资源。
- 真实双人云端完整通过，覆盖对方替换照片时打开的大图更新、打卡删除时清空大图，以及原有全部集成回归。临时账号/空间/图片已清理，原有六表行数不变。首轮测试定位歧义已明确限定到照片墙再重测，没有放宽断言。
- 正式 Pages 发布与线上复测结果将在完成后补记于项目日志。

边界：这是大图查看的同步/隐私补强，不是找回早期已经丢失的原始照片；没有改变双人照片归属或照片删除权限。手机验证仍是 Windows Chromium 触屏模拟，不声称实体安卓/iOS 全机型通过。
