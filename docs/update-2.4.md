# 2.4 · 精细找店、晚餐抽签与月度食记

整理日期：2026-09-17。本轮不修改数据库、存储权限、双人评分或历史记录，不需要重新设置邮箱。

## 怎么使用

- **记录 → 精细筛选**：组合城市、分类、人均范围、日期范围、未填日期和有照片记录。清空按钮同时清除关键词；首页快捷统计会清掉隐藏筛选，避免看到不完整的结果。
- **首页 → 今晚吃啥**：选想吃、想二刷、共同最爱或全部店铺，再按城市、分类与预算抽签；可避开含今天在内的近 7 个日历日。每店一张签，一轮内不重复，抽完后会说明开始新一轮。
- **首页 / 我们 → 月度食记**：按用餐日期回看每月打卡、店铺数、用餐日与平均人均。点日历中有打卡的一天，只看当天食记和照片；可切回整月。未填有效日期另有补充入口。
- **记录详情 → 复制餐厅信息**：只复制店名、城市、分类、地址，方便粘贴到聊天；浏览器不允许自动复制时可以长按文字手动复制。

## 数据口径

- 多条件筛选为交集，先筛选各次打卡，再按原有店铺收纳方式显示；同名不同分店不自动合并。人均上下限、日期端点均包含边界；金额 0 有效，空金额不是 0。输入范围颠倒会明确提示。
- 设定预算时不选择未填金额的店。吃过的店采用最近一次用餐快照，不用历史便宜的一顿冒充现在价格；想吃清单采用最近上传的计划预算。二刷和共同最爱的判断也采用最近一次吃过的评价。
- 同一店同时有想吃与吃过记录时，混合/全部来源优先采用想吃计划；“避开最近吃过”检查该店所有打卡，而不仅检查展示那条计划。
- 抽签只读取已有档案，不查询商家营业状态、不预测实时价格，也不新增记录。没有日期的打卡无法判断是否近期去过。
- 月报按有效的 `YYYY-MM-DD` 用餐日期归月，统计未删除的吃过记录；想吃计划、回收站、未填日期不混入。月度人均是已填人均的打卡平均值，不是两人总花费；不会因为另一半补评而多算一顿。
- 月度照片预览前 12 张，点击可看相应打卡的完整相册。“有照片记录”依据照片元数据，原文件缺失仍需重新上传，不承诺原图一定可读。
- 筛选、月份和抽签偏好仅保留在当前页面会话，不上传为共享设置。底层记录仍使用原本的本机/云端档案；云端变动时打开的月报与抽签同步更新。

## 实现与隐私

- `lib/discovery.js`：纯数据规则、范围验证、按店铺抽签、无放回抽取、月历与统计、可复制文本。
- `lib/discovery-ui.js`：筛选控件、抽签面板、月报和复制界面，复用现有卡片和图片更新机制。
- 退出或切换账号清空新的隐藏弹层、筛选选项、月报、抽签结果、照片引用与待复制文字。复制是用户主动点击，不读取剪贴板；已经由用户复制到系统剪贴板的文字不自动删除。
- 新模块加入离线缓存 `our-food-map-shell-v7`；本机档案离线可用。云端离线保存规则不变。
- 不增加公共分享链接、外部地图定位权限、第三方分析、公共图片或数据库写入入口。

## 技术参考

- [MDN Clipboard.writeText](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)：以主动点击触发异步复制，处理权限拒绝并保留手动复制路径。
- [MDN input month](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/month)：月份输入除浏览器控件外仍进行数据验证，提供上月、下月、本月按钮。
