# 2.7 · 复访小结

整理日期：2026-09-18。沿用“一家店多次独立打卡、双方评价同一顿”的模型，增加回看信息，不改写历史记录或榜单。

## 新增内容

同一稳定店铺有至少两次未删除的吃过记录时，详情页出现可展开的“复访小结”。

- 展示实际打卡次数、已有用餐日期的起止范围、平均每次人均、已填金额的样本数和范围。未填不当 0；0 元有效；想吃预算不计入；不把平均人均写成两人总花费。
- 比较最近两次**有有效用餐日期且双方均评完三项主评分**的记录。每项先取两人平均，再显示味道、性价比、环境的上升/下降/持平。只有一次满足时说明还缺什么，不补造评分。
- 同日按上传时间区分前后；未填日期不推断先后。未评完的最新一顿不与旧评价拼接，不选历史最好的一次。榜单仍沿用原来的独立规则。
- 展示记录中原文填写过的推荐菜；同次打卡两人写同一项只计一次，按最近提及顺序最多展示六项。每项可打开最近一次提及的打卡；不自动拆分菜名或创造新菜品数据。
- 比较日期可点击回到对应那一顿。后台同步后小结保持展开并更新；删除/恢复打卡会相应更新统计。单次到访不显示空的小结。
- 仍只在私人档案内展示；原来的“复制餐厅信息”不增加推荐菜、私人评分或评价。

## 实现和验证

- 新增 `lib/insights.js`，统计按稳定的空间+店铺身份分组，按打卡 ID 去重，不按同名合并分店。
- 四项 Node 专项测试通过：范围隔离、金额、双方评分时序、同日规则、缺日期、推荐语计数、输入转义和不修改源数据/榜单。
- 三项专项浏览器测试通过：展开与跳转、后台刷新、离线回看、删除恢复、推荐语安全转义、320/393/1280px 布局。已查看 393px 截图。
- 全量 36 项 Node、51 项浏览器测试通过，共 87 项。真实双人云端回归通过，打开的小结能即时跟随另一方补评；既有权限、照片、头像、草稿、回收站、榜单与同步兜底均通过。临时测试资源已清理，原有六表行数未变。
- 开发期首次离线测试提示新模块尚未入缓存，完成版本升级和离线清单补齐后通过；离线标题断言也改为检查实际离线状态及记录保留，不修改产品文案迎合测试。
- 资源 2.7.0，缓存 `our-food-map-shell-v12`，发布自检包含 16 模块、24 项离线资源。全量回归与发布结果见项目日志。

无数据库迁移；没有整理、合并、删除或替用户补写正式记录。这个小结是已记录信息的回顾，不是商家经营趋势或客观质量结论。
