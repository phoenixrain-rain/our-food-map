# 2.5 · 待办中心与本机草稿

整理日期：2026-09-18。在 2.4 发布和线上复核完成后继续迭代；没有数据库迁移，也没有代填或修改正式用户记录。

## 待办中心

首页或“我们 → 待办中心”集中查看：我待评分、TA 待评分、补用餐日期、补人均、检查照片。

- 按每次打卡统计，一条记录可以同时有多项待办，不把各项数量相加当作记录总数。
- 双方评价独立，“TA 待评分”只能查看原记录，不提供替对方打分的按钮。空间只有自己一位成员时不产生不存在的对方待评任务。
- 已填写的 0 元有效；想吃计划不用补用餐日期或评价，但可补预算。删除记录不计入任务。
- “检查照片”按元数据中的可用地址判断，包含临时签名失败，不等于原图一定丢失。可以先刷新，真正缺文件时再补图；不自动删除照片。
- 操作只打开对应原记录，不新建副本、不修改双方评分规则、不自动催促或发送消息。
- 补充完成后待办数量随档案更新，保留用餐日期倒序。

## 明确暂存，不冒充同步成功

编辑页底部“先暂存草稿，稍后继续”可保存尚未填完的店名、信息、评分、文字和新选照片；暂存成功后回首页，从草稿卡继续。未填必填店名也能暂存。

- 仅用户主动点击暂存才保存草稿；没有自动草稿或离线云端上传队列。未点击暂存的输入仍需留在当前编辑页。
- 本机 IndexedDB 数据库 `our-food-map-drafts`、仓库 `drafts`，按 `local:local-me:` 或 `cloud:<user>:<space>` 隔离。每个档案在该设备保留一份。
- 保存 JPEG Blob，不存临时 object URL、签名地址、会话令牌或管理凭据。最多 8 张新照片，每张不超过 5 MiB，沿用现有压缩结果。
- 草稿不计入已吃过、月报、榜单或待办，也不上传照片；只有用户正式保存才写入档案并同步给另一半。
- 有效期 7 天；过期草稿在读取时清除。草稿不包含在正式档案导出备份中，也不能跨设备恢复，清除站点数据会丢失。
- 替换已有草稿前确认；删除草稿只删除暂存内容，不动正式记录。删除与暂存均在事务内检查草稿 revision，旧页面不能删除新草稿。
- 恢复时保留原记录版本；另一页面或另一半修改过后，旧草稿仍可查看/复制内容，但不能覆盖新版本。草稿恢复不会规避软删除、所属店铺检查或照片归属规则。
- 正式保存只清除该编辑器恢复的同一份草稿版本；不删除另一页面较新暂存的内容。清理失败明确提示，不把正式保存谎报为失败。
- 主动退出云端账号前清理其各空间草稿；被动切换账号也尝试清理并清空显示。异常清理失败会明确提醒，不声称完成。

## 隐私与维护补强

- 退出账号不仅隐藏页面，还清空详情正文、成员和邀请码、编辑文字、评分、照片预览、头像预览/裁剪画布、相册引用，以及 2.4/2.5 的隐藏摘要。
- 新增 `npm run check:release`：只读检查版本与 lockfile、前端模块引用、离线资源完整性、HTML 重复 ID、label 目标和用户缩放；不联网、不读取正式记录。
- 资源版本 2.5.0，离线缓存 `our-food-map-shell-v8`；新增草稿、待办模块全部进入缓存。本机草稿可离线暂存、重开并正式保存。
- 设置项补齐空格键操作，原生按钮不再被额外模拟一次 Enter 点击。
- “我们 → 使用指南”可直接查看加入空间、给同一顿补评价、再次打卡、草稿、待办、筛选/月报/抽签、手机桌面安装、同步和备份说明，无需再翻聊天记录。
